# Block 13: centralized presentation states

SystemNotice and its pure presenter own reusable search, Gmail, profile-information,
stale-analysis, empty-applications, empty-improvements and clear-dashboard copy.
They do not change application outcomes, candidate facts, product access or evidence.
Actions are labels only, not implicit commands or external calls.

MERGE: Opportunities now consumes centralized running/stopped/error/quota messages,
retaining actual counters, one batch-level quota warning and existing result rendering.
Sources consumes the centralized optional Gmail notice. Existing completed-search
summary remains KEEP because it uses actual counts and target semantics.

REPLACE at remaining V1 view integration: per-page empty/stale/profile/dashboard
messages should consume these contracts when their corresponding authoritative V1
state is available. Do not reinterpret legacy candidate-derived market output as
the new MarketProfile to activate a notice. These remaining routes are not yet
fully integrated; the model alone is not evidence of end-to-end completion.

Application age is attention only: <10 days fresh, 10-20 aging, >=21 old. Missing,
invalid or future timestamps remain unknown (None), not zero days or No Response.
Legacy naive timestamps are interpreted as UTC. No automatic closure/rejection or
scheduled monitoring is implied. There are no raw exceptions/provider responses
accepted by error-copy functions.

Verification still needed: production PostgreSQL migrations, authorized multi-user
browser journeys, the remaining V1 view cutover, real provider/AI adapters, and an
authoritative access/billing adapter. Offline contracts and tests do not certify
those integrations or a production-ready V1.
